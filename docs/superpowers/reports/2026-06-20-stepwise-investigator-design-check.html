ЗадачаРаздел спекиТребование
T1 Direction · Architecture Гибрид: агентный read-only исследователь → один детерминированный PLAN. interpret() и verify() остаются неизменными; мутации только в ops плана. det-execution
T2 Components · slim_gather slim_gather seed = identity + имена таблиц/колонок + пути документов. Без тел политик, без sample-строк, без листингов — они становятся on-demand инструментами исследователя. no-LLM
T3 Components · investigate() · whitelist Read-only ReAct-цикл investigate(). Brief = упорядоченные step-notes + env связанных фактов. Read-only whitelist: sql (SELECT), read, tree, stat, list, search. Попытка мутации → lint reject → урок, шаг повторяется (не крах). read-only
T4 Components · step-scoped oracle oracle.retrieve(step_goal, k=INVESTIGATE_ORACLE_K) по текущей микро-цели, малое k. Заменяет единый K=4 дамп атомов по всей инструкции в PLAN.
T5 Components · sufficiency gate Остановка = достаточность (intent.required_refs / success_criteria заземляемы из brief.env) ИЛИ бюджет (потолок шагов INVESTIGATE_MAX_STEPS).
T6 Model roles — dynamic escalation Динамическая эскалация FAST → REASON на детерминированном стопоре (пустой результат ∨ повтор сигнатуры инструмента). INTENT, финальный PLAN, cross-run distill остаются REASON.
T7 Step lessons · cross-run lessons Уроки оба пути: in-run рабочая память (brief) + cross-run distill → validate_atom_via_grader → promote в oracle. Только общее/валидированное знание.
T8 Configuration (new env vars) Конфиг: ECOM_INVESTIGATE_ENABLED (1; 0 = legacy eager gather для A/B), ECOM_INVESTIGATE_MAX_STEPS (6), ECOM_INVESTIGATE_ORACLE_K (2), ECOM_MODEL_INVESTIGATE. Legacy gather_prephase_facts сохранён за тумблером.
T9 Error Handling Бережная обработка ошибок: tool error / пустой результат / mutation-attempt / необработанное исключение → graceful fallback на slim-seed в PLAN. Никогда не хуже baseline.
T10 Testing / Success Criteria · Trace Тесты: unit (MockVMSpy) + integration + реальный t38 grader-gate (score 0 → >0, падение [plan] user prompt chars, отсутствие 492 s CC-таймаута) + trace-фаза INVESTIGATE.
T11 v1 simplification · Out of Scope v1: Brief строится один раз и заморожен на прогон. Re-investigation по фидбэку verify() и confidence-эскалация — вне области v1.

2. Схемы решения и зависимостей

2.1. Схема решения — конвейер на задачу

slim_gather → INTENT → цикл investigate (router → tool → digest → sufficiency/budget) → цикл PLAN (lint → interpret → verify) → answer / distill. Тиры: FAST (router/digest), REASON (INTENT / PLAN / distill). Сплит: read-only исследователь vs мутирующие ops плана.

2.2. Граф зависимостей — компоненты «uses / depends on»

Узлы = компоненты; рёбра = «использует» / «зависит от». Зелёная рамка = детерминированный/неизменный; синяя = новый LLM-компонент; жёлтая = конфиг/тир-метка.
