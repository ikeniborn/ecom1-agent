Diagnosis (from the treatment trace)

The decisive criterion failed. Root cause is not context overload, so the investigator (a context-efficiency mechanism) cannot fix it:

  1. The baseline fails with full context too. t38 OFF carries the entire eager facts dump (all doc bodies + identity + samples, ~29k chars) and still returns DENIED_SECURITY. The failure is a decision/grounding error, not floundering-from-overload. Shrinking the prompt (the investigator's job) is therefore not expected to flip it — and didn't.
  2. Weak model. The benchmark ran on deepseek-v4-flash:cloud, which fails both t38 and t01 at baseline. The plan's t38 fix presumed a Claude-Code-tier timeout/floundering symptom; under this model the bottleneck is reasoning capability, not prompt size. t38 is also a known-hard task (prior note: fraud "impossible-leg" caps ~73%).
  3. Investigator flaw surfaced (minor, not the t38 root cause). In the t38 ON brief, the router correctly read /docs/security.md then tried /bin/id to confirm identity — but is_readonly rejects all exec except /bin/sql, so /bin/id was rejected twice and the router gave up (done). The brief bound only policy_doc:/docs/security.md and never the identity. This is wasted steps + brief noise, not the t38 score cause: the slim seed still gathers identity into facts.identity (kept in both modes), which reaches PLAN regardless — and PLAN still denied. Still, /bin/id is a legitimate read-only identity probe the investigator should be allowed to run on demand.

Verdict

The INVESTIGATE feature (Tasks 1–14) is implemented and works as designed: it builds a compact brief, runs strictly read-only, cuts the PLAN prompt ~55–60%, reduces cycles/wall-clock, traces under the INVESTIGATE phase, and degrades gracefully — all behind ECOM_INVESTIGATE_ENABLED with the =0 baseline preserved exactly (108 deterministic-core tests + 30 investigator unit tests green). The mechanical efficiency goals are met. The hoped-for t38 score flip (0→>0) was not achieved on this model run, because the t38 failure is decision/capability-bound, not context-bound.

Recommendations (not done here — for a follow-up decision)

  • Allow /bin/id (and only that) in investigate.is_readonly exec whitelist — it is a read-only identity probe; today the investigator wastes steps on it. Small, well-scoped; will not by itself flip t38 (identity already flows via the slim seed).
  • Re-run the gate on a stronger model (Claude tier) before judging the t38 hypothesis — the plan's floundering/timeout premise targets the CC tier, not deepseek-flash.
  • t38's DENIED_SECURITY decision is a LEARN/oracle + model-capability problem, not a pre-phase problem; pursue it via the LEARN rule (never data/prompts/), separately from this feature.
