2. Схемы решения и зависимостей

Схема решения — три кластера и затрагиваемые файлы

Cluster A — PLAN robustness  🔴 critical
H1 — достижимый CC-cfg + bounded retries
C2 — кросс-провайдер fallback на empty
C1 — fail-fast (производное H1+C2)
agent/llm.py · agent/cc_client.py · agent/reason.py
Cluster B — INVESTIGATE correctness  🟠 high
H2 — детерминированный grounding governing-doc
H3 — authority-confirmed сигнал вместо proxy
M3 — слияние digest + next-router
agent/investigate.py (+ LEARN-канал)
Cluster C — Observability  🟡 low
M1 — cache-токены в run-summary
M2 — parsed_output в trace (INTENT/PLAN)
agent/trace.py · run-summary builder

Порядок реализации (§10): Cluster A → Cluster B → Cluster C (по возрастанию риска / убыванию приоритета).
