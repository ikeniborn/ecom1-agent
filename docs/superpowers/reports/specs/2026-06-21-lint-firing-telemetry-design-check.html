1. Резюме спецификации

Спецификация описывает первый срез будущего моста обратной связи harness → oracle: инструментирование того, какие data/harness/checks.yaml проверки срабатывают, чтобы направление моста выбиралось по реальным данным. Только телеметрия.

СекцияТребование (по одному в строке)
Background / Problem oracle (мягкий, позитивный, ранжируется ретривалом, NL-атомы) и harness (жёсткий, негативный, детерминированный гейт, code-backed check-specs) — двусторонний цикл «генерация-затем-проверка», не избыточность.
Единственное направление обратной связи с «топливом» сегодня — «teach»: срабатывающая проверка → method-атом.
Блокер: нет per-check сигнала срабатывания (lint() только print(); log_gate — агрегат passed/blocked; warn-срабатывания невидимы).
Scope Инструментировать срабатывание lint + offline-отчёт. ТОЛЬКО телеметрия — без дистилляции, без изменения oracle, без авто-промоции, без env-gate.
Non-Goals Нет: дистилляции method-атомов; записи в data/oracle/; авто-промоции; новой env-переменной; упрочнения anti-атомов (их ноль); нового always-on event-файла (переиспользуем trace-канал, не history.jsonl).
Architecture · Unit 1 — Emit (agent/trace.py) Новый log_lint_fire_auto(check_id, kind, severity, blocking, message); best-effort, никогда не бросает; запись {type:lint_fire, cycle, check_id, kind, severity:error|warn, blocking, message}; task_id/seq/ts штампует TraceLogger._write; новый метод TraceLogger.log_lint_fire + thread-local обёртка.
Architecture · Unit 2 — Wire-in (interpreter.py:lint()) Для КАЖДОЙ сработавшей проверки (blocking И warn) вызвать log_lint_fire_auto до действия; emit предшествует существующему raise/print — семантика неизменна. Известное ограничение: lint() бросает на первой blocking-проверке → за цикл фиксируется только первый блокер; задокументировано, не чинится.
Architecture · Unit 3 — Report (scripts/lint_report.py) Offline-агрегатор, без LLM/grader; сканирует {tid}.jsonl + {tid}.c{N}.jsonl; колонки check_id, kind, fires, blocked, warned, distinct-tasks, sample; ранжирование по сумме срабатываний; trace-каталог аргументом.
Data Flow lint(plan) → per check → log_lint_fire_auto → {tid}.jsonl → render_trace → {tid}.detail.log; прогон бенчмарка → много {tid}.jsonl → lint_report.py → ранжированная таблица в stdout.
Rendering Добавить ветку lint_fire в диспетчер event() функции render_trace → строка · [lint_fire] c<cycle> <check_id> [BLOCK|warn] <message-head>.
Error Handling log_lint_fire_auto глотает все исключения (как log_vm_auto/log_gate_auto); поведение lint() иначе неизменно; lint_report.py терпит битый JSONL (skip-and-continue) и пустой каталог («no lint_fire records»).
Testing (a) Emit — триггер одного error + одного warn, два lint_fire-record с верными blocking-флагами + run всё ещё бросает на blocking; (b) No-trace safety — log_lint_fire_auto без логгера → no-op, no raise; (c) Render — lint_fire-record через render_trace, проверка формата строки; (d) Report — lint_report.py на каталог-фикстуру из 2 файлов, проверка агрегатов на check_id.
Open Questions Ничего блокирующего; stdout-таблица по умолчанию, HTML-вариант — тривиальный follow-up.
