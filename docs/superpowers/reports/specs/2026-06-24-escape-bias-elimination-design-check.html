1 · Резюме спецификации

Требования по фазам

ФазаБакетТребование
Фаза 1
Resolve-or-prove		B1 · ~14 задач Нормализованный probe резолва (agent/resolve.py): прогрессивная релаксация exact → normalized (trim/case/whitespace/unit-suffix '8 l'↔'8') → token-subset LIKE; реальный SKU/record_path в Brief.env
investigate.sufficient() больше не пунтит резолв ключевой сущности на PLAN — ref с источником record_path должен быть фактически найден
Запрет «0 строк ⇒ не существует» для презюмируемо-существующей сущности: пустой резолв → лестница релаксации, UNSUPPORTED только после её исчерпания
Фаза 2
No ungrounded denial		B2 · ~10 задач decide понижает PLAN-авторский DENIED_SECURITY до следующего исхода лестницы, если ни один объявленный security deny_when не держится; легитимные отказы (с holding-предикатом) сохраняются
Фаза 3
Prompt diet + structured chain		B3 + множитель Выкинуть CREATE INDEX dump из фактов; заменить компактным списком table(col,…)
Фиксированный минимальный скелет PLAN-промта; learned/oracle блоки делимитированы и капнуты
Декомпозиция монолитного PLAN в structured-output цепочку (resolve→compute→answer, tiny-schema + CoT); оценить замену ReAct на детерминированную probe-секвенцию — flag-gated A/B
Никакого нерендеренного шаблона в message (t53); вычисленный ответ ⇒ не-escape outcome (t05/t07)
Фаза 4
LEARN hygiene		анти-регресс Детектор противоречий в apply_learn_diff: новое правило с противоположным outcome-гайдансом деактивирует старое (t20: r001↔r006)
Дистилляция семантики данных вместо водопровода (на empty-resolve → «сэмпли реальные значения / релаксируй матч»)
Жёсткий ECOM_LEARN_MAX_ACTIVE + дедуп near-duplicate активных правил
Фаза 5
Reliability первая по импл-порядку		B5 Жёсткий таймаут на КАЖДЫЙ сетевой вызов (LLM-провайдеры, Ollama-embed, BitGN RPC)
Per-task wall-clock бюджет → при превышении терминальный outcome; один таск не морозит прогон, SubmitRun отрабатывает

Success criteria

#Критерий приёмки
1Полный прогон deepseek-flash завершается без зависания и выдаёт grader-скоры
2Распределение submitted-outcome решительно сдвигается от escape; B1 «not found» и B2 spurious-denial в основном устранены (легитимные отказы сохранены)
3Вход PLAN-вызова падает ≥25% (от текущих ~3 080 tok) после удаления schema-dump
4Никаких новых task-specific правил в промтах; всё изменение поведения — в коде
5Существующие тесты зелёные; новые пер-фазовые тесты проходят
